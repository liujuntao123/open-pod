# Convert retains the web service and adds an independent companion Skill

The document conversion capability will keep `apps/convert` as a usable Web/API service and add a Codex `convert` Skill with its own orchestration and execution system. The Skill does not call or require the Web service, its SQLite database, or its job queue. It may study and port proven PDF/EPUB algorithms from the existing implementation, but the installed Skill must run without an Open Pod checkout and must not import workspace packages at runtime. Both systems write beneath `OPEN_POD_CONVERT_DATA_DIR` (default `~/.open-pod-convert`): the Web service owns `jobs/`, while the Skill owns `skill-jobs/` and uses an independent `input/`, `work/`, `output/`, and `result.zip` layout. Neither system manages the other's jobs, and the Skill definition remains outside the runtime data root.
