# v1 UI has three primary surfaces

Information architecture is intentionally small:

1. Work List — enter/create/open works
2. Work Bench — script-driven production for one work (chapters, structured lines, work characters, overrides, preview, synthesize, job progress)
3. Studio Settings — provider connections/secrets, voice library, concurrency, data directory

Workbench-internal layout: chapter list, structured line editor, side panel for character/line params and actions, plus a job progress drawer/strip. Global voice library and provider connections live in Settings, with quick pick/create when binding a voice on a work character.

A fragmented multi-route “editor / cast / jobs / settings” app shell is rejected for v1 local studio density.
